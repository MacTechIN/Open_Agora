# 00. 제품 정의 및 기능 상세 명세

## 1. 제품 정의

CivicAgora는 **진영 논리와 권위적 개입 없이 주권자인 시민 누구나 동등한 자격으로 정책을 검증하고 대안을 만드는 탈중앙 공론장**입니다.

정당·정부·단체도 특권 없이 개인 회원과 동일한 자격으로 참여합니다. 기관 계정이라는 개념 자체가 존재하지 않습니다.

### 1.1 세 가지 설계 원칙

이 세 원칙은 서로를 제약합니다. 기능을 추가할 때 어느 하나를 희생시키지 않는지 반드시 검토해야 합니다.

1. **무신뢰 불변성** — 중앙 서버가 데이터를 검열·삭제·왜곡할 수 없습니다. 본문은 P2P 계층에, 상태 증명만 온체인에 남습니다.
2. **진영 논리 차단** — 다수결이 아니라 *브리징*으로 순위를 매깁니다. 상반된 이념 집단 **양쪽 모두**에게 긍정 평가를 받은 글만 상위에 노출됩니다. 몰표·좌표찍기는 구조적으로 무력화됩니다.
3. **처벌이 아닌 유도** — AI는 차단기가 아니라 작성 단계의 코치입니다. 사용자는 항상 원문 강행 게시를 선택할 수 있고, 대신 평판 차감과 디랭킹을 감수합니다.

### 1.2 용어 정의

기존 문서에서 "3축"이라는 표현이 서로 다른 두 개념에 혼용되어 폐기했습니다. 아래 용어만 사용합니다.

| 용어 | 의미 |
|-|-|
| **안건(Policy)** | 토론의 대상. 현안·정책·정치이슈·문제고발을 모두 포함한다 |
| **토론 카드(DebateCard)** | 안건에 대한 한 시민의 의견. 3단 구조화 입력으로 작성한다 |
| **3열 토론 구조** | 찬성 / 대안·합의 / 반대 세 개의 열로 카드를 배치하는 화면 구조 |
| **3단 구조화 입력** | 카드 하나를 작성할 때 채우는 세 개의 필수 필드 |
| **댓글(Reply)** | 토론 카드에 달리는 자유 서술 응답 |
| **반응(Reaction)** | 카드에 대한 4종 이모지 평가. 브리징 알고리즘의 입력 신호 |
| **필명(Pseudonym)** | 공개되는 유일한 신원. 변경 불가 |

## 2. 3열 토론 구조

안건 하나가 등록되면 화면은 세 개의 동등한 열로 나뉩니다.

```
                    [ 안건: 탄력 근로제 개선안 ]
                    참여 시민 12,480명 · 수렴도 72.4%

  ┌── 찬성 ──────┐   ┌── 대안 · 합의 ───┐   ┌── 반대 ──────┐
  │  SUPPORT     │   │   ALTERNATIVE    │   │   OPPOSE     │
  ├──────────────┤   ├──────────────────┤   ├──────────────┤
  │ 카드 💡142 🤝98│   │ ★ 합의 배너      │   │ 카드 💡88 ⚖️31│
  │   └ 댓글 12   │   │   양 군집 60%+   │   │   └ 댓글 7    │
  │ 카드 💡96 🔍11│   │ 카드 (브리징순)   │   │ 카드 💡54 🔍20│
  │ 카드 …        │   │ 카드 …           │   │ 카드 …        │
  └──────────────┘   └──────────────────┘   └──────────────┘
     최신순/브리징순      브리징 점수순          최신순/브리징순
```

* **좌우 열(찬성·반대)** 은 시각적으로 완전히 동등합니다. 폭·색·정렬 어느 것도 한쪽을 우대하지 않습니다.
* **가운데 열(대안·합의)** 은 브리징 알고리즘의 산출물입니다. 양 이념 군집 모두에서 60% 이상 찬성을 받은 카드가 최상단 **합의 배너**로 승격됩니다.
* 각 열 상단에 카드 수와 댓글 수를 표시합니다.

### 2.1 스탠스 값

```
enum StanceType { SUPPORT | ALTERNATIVE | OPPOSE }
```

작성자가 카드 작성 시 직접 선택하며, 등록 후 변경할 수 없습니다. `ALTERNATIVE`는 "찬성도 반대도 아닌 제3안"을 뜻하며, 가운데 열에만 배치됩니다.

## 3. 3단 구조화 입력 (토론 카드)

감정적 선동을 억제하기 위해 단일 텍스트 박스를 제공하지 않습니다. 세 필드 모두 필수이며, 합계 정확히 **500자**입니다.

| 필드 | 필드명 | 최대 | 유효성 검증 |
|-|-|-|-|
| **1** | 문제 정의 (Context) | 150자 | 특정 정당·인물 고유명사 비난 감지 시 AI 경고 |
| **2** | 데이터 및 팩트 근거 | 200자 | 출처 URL **1개 필수** (별도 필드, 글자수 미포함) |
| **3** | 실행 가능한 해결책 | 150자 | "폐지하라"식 단답 불가. 대안 메커니즘 서술 필요 |

**근거 URL 정책**: 필수입니다. 통계청, 정부 고시·공고, 국회 의안정보시스템, 학술 논문(DOI), 공인 언론 보도를 허용 도메인 화이트리스트로 관리합니다. 화이트리스트 밖 URL은 등록은 가능하되 카드에 "미검증 출처" 배지가 표시되고 브리징 가중치가 감쇄됩니다.

> 기존 스키마는 `evidenceUrl`을 선택 필드로 정의했으나 UI 스펙은 필수로 규정해 충돌했습니다. **필수로 확정**했습니다(→ `08_DECISIONS.md` D8).

## 4. 댓글 (Reply)

각 토론 카드 아래에 지지·반박 댓글을 답니다.

* **분량**: 자유 서술 500자. 카드와 달리 3단 구조를 강제하지 않습니다.
* **깊이**: 1단계만 허용합니다(댓글의 댓글 없음). 스레드가 깊어지면 진영 간 소모적 설전으로 흐르기 때문입니다.
* **AI 톤 코칭**: 카드와 동일하게 적용됩니다.
* **반응**: 댓글에는 반응을 달 수 없습니다. 브리징 신호는 카드 단위로만 수집합니다.
* **평판**: 댓글 작성 자체로는 점수를 얻지 않습니다. 악의적 비방 댓글은 감점 대상입니다.

## 5. 반응 (Reaction)

카카오톡 이모지처럼 선택하고 집계 수가 카드에 표시됩니다. 브리징 알고리즘은 이진 신호 `r ∈ {0,1}`를 요구하므로 긍정 2종·부정 2종으로 고정합니다.

| 이모지 | 라벨 | 신호 | 의미 |
|-|-|-|-|
| 💡 | 논리적이에요 | `r = 1` | 동의 여부와 무관하게 논증이 타당하다 |
| 🤝 | 공감해요 | `r = 1` | 주장에 동의한다 |
| 🔍 | 팩트체크 필요해요 | `r = 0` | 근거의 사실관계가 의심스럽다 |
| ⚖️ | 이견 있어요 | `r = 0` | 논지에 동의하지 않는다 |

**설계 의도**: 💡는 "내 진영은 아니지만 말은 맞다"를 표현하는 통로입니다. 이 버튼이 브리징 점수를 만들어내는 핵심이므로, UI에서 가장 먼저·크게 배치합니다. 반대로 원본 요구의 "좋아요/추천해요", "반대해요/별로에요"는 의미가 중복되어 신호 품질을 떨어뜨리므로 채택하지 않았습니다(→ D4).

* 한 사용자는 카드 하나당 하나의 반응만 남길 수 있고, 변경은 가능합니다.
* 자신의 카드에는 반응할 수 없습니다.
* 반응자의 신원은 집계에만 쓰이고 **누가 무엇을 눌렀는지는 누구에게도 공개되지 않습니다**(→ `02_IDENTITY_PRIVACY.md`).

## 6. 안건(정책) 등록 포맷

안건 등록도 자유 서술이 아니라 고정 포맷을 따릅니다. 등록자 역시 일반 회원이며 특권이 없습니다.

| 필드 | 최대 | 필수 | 설명 |
|-|-|-|-|
| 제목 | 60자 | ✅ | 중립적 서술. 찬반 유도형 제목 금지(AI 검사) |
| 분류 | — | ✅ | `정부정책` \| `입법안` \| `정당정책` \| `지자체` \| `공공기관` \| `사회현안` \| `문제고발` |
| 배경 요약 | 300자 | ✅ | 안건이 왜 지금 논의되어야 하는지 |
| 쟁점 질문 | 100자 | ✅ | 토론이 답해야 할 단일 질문 |
| 공식 출처 | URL | ✅ | 법령·의안·보도자료 등 1차 자료 링크 |
| 소관 기관 | — | ⬜ | 대정부 브리프 발송 대상. 미지정 시 운영 단계에서 분류 |
| 토론 기한 | 날짜 | ⬜ | 미지정 시 등록일로부터 90일 |

**중복 방지**: 등록 시 제목·본문 임베딩 유사도로 기존 안건을 검색해 유사 안건을 먼저 제시합니다. 중복 난립은 여론을 분산시켜 브리징 표본을 망가뜨립니다.

**등록 자격**: 평판 점수 50점 이상. 신규 가입자의 대량 안건 생성을 막기 위한 최소 장벽입니다.

## 7. 영구 보존과 블라인드 정책

원본 요구는 "AI가 문제 글을 삭제한다"와 "글은 영원히 삭제되지 않고 검색된다"를 동시에 담고 있었고, 블록체인 불변성과도 충돌했습니다. **삭제를 폐지하고 3단계 노출 조정으로 확정**했습니다(→ D3).

| 단계 | 조건 | 처리 |
|-|-|-|
| **1. 디랭킹** | 톤 코칭 순화 권고 거부 후 게시 | 정렬 순위 하락. 내용은 그대로 보임 |
| **2. 블라인드** | 커뮤니티 신고 누적 + AI 유해성 재확인 | 본문 가림. "가려진 글 보기" 클릭 시 표시 |
| **3. 검색 제외** | 명백한 불법·음란·중대 명예훼손 | 검색·목록에서 제외. 직접 링크로는 열람 가능 |

**어느 단계에서도 원문은 IPFS에서 제거되지 않으며 온체인 머클 앵커도 유지됩니다.** 블라인드는 UI 계층의 표시 규칙일 뿐이고, 독립 노드 운영자는 언제나 원문을 검증할 수 있습니다. 이것이 "누구도 지울 수 없다"는 원칙을 지키는 방식입니다.

블라인드 처리 이력 자체도 공개 로그로 남겨 운영 주체의 자의적 개입을 감시할 수 있게 합니다.

## 8. 랭킹과 검색

* **회원 랭킹**: 평판 점수 기준 1위부터 전체 순위를 공개합니다. 본인·타인 모두 점수와 등수를 검색할 수 있습니다.
* **검색 대상**: 안건, 토론 카드, 필명. 검색 제외 처리된 글은 결과에서 빠집니다.
* **랭킹에 노출되는 정보**: 필명, 점수, 등수, 배지, 가입 시점의 연도(월일 제외)뿐입니다. 정치 성향·정당 정보는 **어떤 경로로도 노출되지 않습니다**.
