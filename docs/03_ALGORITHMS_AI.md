# 03. 알고리즘 및 AI 파이프라인

## 1. 브리징 행렬 분해 (Bridging Matrix Factorization)

X(구 Twitter) Community Notes 알고리즘을 정책 토론에 맞게 변형합니다. 목적은 하나입니다. **특정 진영의 몰표로는 상위 노출을 살 수 없게 만드는 것.**

### 1.1 평점 예측 모델

사용자 `u`가 카드 `i`에 남긴 반응을 `r(u,i) ∈ {0,1}`로 둡니다(💡🤝 → 1, 🔍⚖️ → 0).

$$\hat{r}_{u,i} = \mu + b_u + b_i + f_u \cdot f_i$$

| 기호 | 의미 |
|-|-|
| $\mu$ | 플랫폼 전체 평균 반응률 |
| $b_u$ | 사용자 $u$의 관대함 지수 (항상 긍정을 누르는 사람인지) |
| $b_i$ | **카드 $i$의 고유 품질 = 브리징 점수.** 랭킹의 기준값 |
| $f_u \in \mathbb{R}^d$ | 사용자 $u$의 잠재 정치 성향 벡터 ($d=1$이면 좌우 축) |
| $f_i \in \mathbb{R}^d$ | 카드 $i$가 특정 진영에 어필하는 편향 벡터 |

### 1.2 목적 함수

$$\mathcal{L} = \sum_{(u,i) \in \mathcal{O}} \left( r_{u,i} - \hat{r}_{u,i} \right)^2 + \lambda \left( b_u^2 + b_i^2 + \|f_u\|_2^2 + \|f_i\|_2^2 \right)$$

### 1.3 왜 몰표가 무력화되는가

이 문서 전체에서 가장 중요한 성질입니다. **랭킹 코드를 수정할 때 반드시 회귀 검증해야 합니다** (VS-F2, `services/bridging/test_bridging.py`).

특정 진영이 좌표를 찍어 대량으로 💡를 누르면, 그 집단의 $f_u$와 카드의 $f_i$ 방향이 일치해 내적 $f_u \cdot f_i$ 항이 커집니다. 손실을 줄이는 과정에서 **관측된 긍정 반응이 이 내적 항만으로 설명되어 버리므로, 고유 품질 $b_i$는 올라가지 않습니다.**

> **⚠ 이것은 저절로 되지 않습니다 (2026-09-24 실측).**
>
> §1.4가 원래 정규화를 $\lambda = 0.15$ 하나로만 적었는데, 그대로 구현하면 **몰표가 브리징을 이깁니다.** 합성 데이터 4벌 중 2벌에서 뒤집혔습니다.
>
> 이유는 **공선성**입니다. 한 진영만 반응하면 그 사람들의 $f_u$가 거의 상수이므로 설계행렬 $[\,1,\ f_u\,]$의 두 열이 거의 평행해집니다. 이때 릿지 회귀는 **노름이 큰 쪽**, 즉 상수열(절편)로 설명을 몰아줍니다. 몰표의 긍정이 편향 $f_i$가 아니라 품질 $b_i$로 들어가 버립니다.
>
> 그래서 **절편을 인자보다 강하게 정규화해야 합니다**($\lambda_b \gg \lambda_f$). 절편이 비싸지면 같은 설명을 $f_i$로 하는 편이 싸집니다. 양 진영이 모두 긍정한 카드는 $f_u$의 부호가 갈려 $f_i$로 설명할 수 없으므로, 절편이 비싸도 $b_i$가 올라갑니다 — 그것이 우리가 원하는 성질입니다.
>
> 배수의 하한은 대략 $1/|f_u|^2$입니다(인자열의 노름이 상수열의 $|f_u|$배이므로). 실측 $|f_u| \approx 0.5$이므로 하한이 4 근처이고, 여유를 두어 **10**으로 둡니다. → `08_DECISIONS.md` D23

반대로 $f_u$ 부호가 서로 반대인 두 집단이 모두 긍정 반응을 보내면, 내적 항으로는 양쪽을 동시에 설명할 수 없습니다. 이때 남은 오차를 흡수할 수 있는 유일한 항이 $b_i$이며, 그제서야 $b_i$가 큰 양수가 되어 상위에 노출됩니다.

> **한 줄 요약**: 내 편만 밀어주면 편향 벡터가 흡수하고, 반대편까지 인정해야 품질 점수가 오른다.

### 1.4 학습 파라미터

| 항목 | 값 | 비고 |
|-|-|-|
| 잠재 차원 $d$ | 1 | 초기에는 좌우 단일 축. 데이터 축적 후 2로 확장 검토 |
| 인자 정규화 $\lambda_f$ | 0.15 | $f_u$, $f_i$ 에 적용 |
| 절편 정규화 $\lambda_b$ | **1.5** ($= 10\lambda_f$) | $b_u$, $b_i$ 에 적용. **§1.3의 성질이 이 비대칭에 달려 있습니다** |
| 최적화 | **ALS** | 각 단계가 닫힌 해라 학습률·수렴 판정이 없습니다. 같은 입력이면 같은 출력 |
| 최소 반응 수 | 카드당 20개 | 미만이면 $b_i$ 미산출, "평가 수집 중" 표시 |
| 재학습 주기 | 일 1회 (KST 04:00) | 스냅샷 해시·모델 버전·시드를 산출물에 기록 |

$b_i$ 미산출 카드는 최신순으로만 노출되며, 이 구간이 신규 카드의 노출 기회를 보장합니다.

## 2. Pol.is 합의 추출

### 2.1 절차

1. **희소 행렬 구성** — 시민 × 카드 반응 행렬 $M_{m \times n}$ (긍정 1, 부정 0, 미반응 결측).
2. **PCA** — 제1·제2 주성분으로 2차원 투영. 여론 지형도 시각화에 그대로 사용합니다.
3. **K-Means 군집화** — 이념적으로 대립하는 대표 군집 추출. $k$는 실루엣 계수로 2~5 범위에서 자동 선택합니다.
4. **합의 대안 추출** — 아래 조건을 만족하는 `ALTERNATIVE` 카드를 가운데 열 상단 **합의 배너**로 승격합니다.

$$\text{Consensus}(i) = \min_{k \in \text{Clusters}} \left( \frac{\sum_{u \in C_k} \mathbb{I}(r_{u,i} = 1)}{|C_k|} \right) \ge 0.60$$

```
   군집 A (우려 중심)                     군집 B (원안 지지)
      [ Cluster 1 ]                          [ Cluster 2 ]
            \                                      /
             \                                    /
              ──►  [ Common Ground : 제3의 대안 ]  ◄──
                     양 군집 각각 60% 이상 찬성
```

### 2.2 임계치 확정: 0.60과 0.65는 충돌이 아니다

기존 두 문서가 0.65와 0.60으로 달라 충돌로 보였으나, 검증 결과 **서로 다른 두 관문**으로 정합화하는 것이 타당했습니다(→ D5).

| 관문 | 임계치 | 용도 |
|-|-|-|
| **1차: 합의 배너 승격** | 모든 군집에서 ≥ **0.60** | 플랫폼 내 가운데 열 상단 노출 |
| **2차: 대정부 브리프 수록** | 모든 군집에서 ≥ **0.65** 이며 군집 간 찬성률 격차 ≤ **5%p** | 국회·부처로 공문 발송 |

2차 기준이 더 엄격한 이유는 외부 기관에 공식 발송되는 문서의 무게 때문입니다. 이 해석은 기존 브리프 예시의 "지지도 84.1%, 양 진영 지지율 격차 3.2% 이내"라는 서술과도 정확히 들어맞습니다.

**최소 인원**: 인원 20명 미만 군집은 찬성률을 산출하지 않고 판정에서 제외합니다(INV-5).

## 3. AI 톤 코칭 파이프라인

사용자를 처벌하는 것이 아니라 작성 단계에서 건설적 문장으로 유도합니다.

### 3.1 3단계 추론

```
[사용자 입력 500자]
        │
        ▼
[Step 1: 고속 스크리닝 — KcELECTRA-base-v2022]
   지연시간 < 30ms · 매 입력마다 실시간 실행
   정치 커뮤니티 신조어·은어·초성 비하 탐지에 강함
        ├── score < 0.30 ──► 정상 승인. 패널티 없음. 여기서 종료
        └── score ≥ 0.30 ──► Step 2 진입
        │
        ▼
[Step 2: 정밀 멀티라벨 분류 — smilegate-ai/kor_unsmile]
   10개 카테고리: 악플, 지역차별, 연령비하, 젠더혐오, 인종·국적,
                  종교, 기타혐오, 욕설, 클린, 개인지칭
   비난 대상 분리: "인물·정당 비방" vs "정책적 문제 지적"
        ├── toxicity < 0.65 ──► 경고 없이 통과. 내부 기록만
        └── toxicity ≥ 0.65 ──► Step 3 진입 및 인라인 배너 트리거
        │
        ▼
[Step 3: 순화문 생성 — yanolja/EEVE-Korean-Instruct-10.8B]
   핵심 비판 논거는 100% 보존, 표현만 공론장 어휘로 변환
        │
        ▼
[클라이언트 인라인 인터스티셜]
        ├── [순화문 적용] ──► 평판 점수 100% 보존
        └── [원문 게시]   ──► -30점 및 디랭킹 (wasRevisionRejected = true)
```

### 3.2 임계치 확정: 0.30과 0.65도 충돌이 아니다

기존 두 문서의 0.3과 0.65 역시 **파이프라인의 서로 다른 게이트**로 정합화됩니다(→ D6).

* **0.30 — 1차 통과 게이트.** 이 아래는 무조건 무해로 판정하고 추가 연산을 하지 않습니다. 대부분의 입력이 여기서 끝나므로 서버 비용이 통제됩니다.
* **0.65 — 2차 배너 트리거.** 실제로 사용자에게 경고를 띄우고 순화를 권하는 기준입니다.
* 0.30~0.65 구간은 **회색지대**입니다. 경고하지 않고 통과시키되 점수는 기록합니다. 무해한 강한 어조까지 경고하면 코치가 잔소리로 전락해 사용자가 이탈하기 때문입니다.

모델 순서도 확정합니다. **KcELECTRA(고속) → KorUnsmile(정밀)** 입니다. 무거운 멀티라벨 분류기를 모든 타이핑마다 돌릴 수 없으므로, 가벼운 모델이 먼저 걸러야 합니다. 기존 `01` 문서의 역순 서술은 폐기되었습니다.

### 3.3 순화 프롬프트

```jinja
System: 당신은 대한민국 국회 입법조사관 수준의 어휘를 구사하는 중립적 정책 코치입니다.

User: 아래 문장에서 감정적 비난, 냉소, 인신공격을 제거하고
      사실 중심의 정중한 반박문으로 재작성하십시오.

규칙:
1. 작성자의 본래 주장과 비판 취지는 100% 보존할 것.
   비판의 강도를 낮추거나 결론을 바꾸지 말 것.
2. 정책적 사실관계와 논거 위주로 문맥을 다듬을 것.
3. 원문과 동일한 필드의 글자 수 제한을 지킬 것.
4. 새로운 사실이나 근거를 지어내지 말 것.

[원문]
"{{ raw_user_text }}"

[출력 형식: JSON]
{
  "toxicity_score": 0.82,
  "detected_violations": ["비아냥/조롱", "인신공격"],
  "suggested_revision": "해당 지원금 정책은 예산 추계의 구체성이 부족하여 중장기적 재정 건전성을 악화시킬 위험이 있습니다."
}
```

**규칙 1과 4가 핵심입니다.** 순화가 주장을 무디게 만들면 이 기능은 검열이 됩니다. 비판의 세기는 유지하고 표현만 바꿔야 합니다. 정기적으로 원문·순화문 쌍을 표본 검수해 논지 보존율을 측정해야 합니다.

### 3.4 서빙 구성

* FastAPI + vLLM. Step 1·2는 ONNX Runtime으로 양자화해 CPU 추론.
* Step 1은 클라이언트 온디바이스 실행을 목표로 합니다. 타이핑 내용을 서버로 보내지 않는 것이 프라이버시상 크게 유리하며, 네이티브 앱이므로 실현 가능합니다(→ `05_CLIENT_APPS.md`).
* Step 3만 서버 호출이 필요하며, 이 시점에는 사용자가 이미 작성을 마친 상태입니다.

## 4. 알고리즘 검증 가능성

계층 3의 모든 산출물에는 다음 메타데이터를 첨부해 계층 2에 서명 저장합니다.

```json
{
  "job": "bridging_mf",
  "version": "1.0.0",
  "input_snapshot_root": "0x9f4a...e12d",
  "model_params": { "d": 1, "lambda": 0.15, "seed": 20260921 },
  "computed_at": "2026-09-21T04:00:00+09:00",
  "output_root": "0x71c8...aa03"
}
```

제3자가 동일 스냅샷으로 재계산해 `output_root`가 다르면 조작을 증명할 수 있습니다. 이것이 연산 서버를 신뢰하지 않고도 쓸 수 있게 하는 장치입니다.
