# 06. 대정부 브리프 및 연구자 오픈 API

## 1. 대정부 합의 브리프

### 1.1 발행 조건

> **구현됨 (VS-H1, 2026-09-28)** — `web/lib/brief.ts`, 확인 `web/scripts/e2e-brief.mjs`.
> 아래 표는 D18로 하향된 현재 기준입니다.

| 조건 | 기준 | 세는 방법 |
|-|-|-|
| 누적 의견 | **100건** 이상 | 해당 안건의 카드 수 |
| 참여 시민 | **50명** 이상 | 반응에 쓰인 **익명 필명**의 distinct 수 |
| 이념 군집 | 2개 이상 형성 | 인원 20명 이상 군집만 셈 |
| 합의 대안 | 2차 관문 통과 카드 1건 이상 | `ALTERNATIVE` 열만 |

2차 관문은 **모든 군집에서 찬성률 ≥ 0.65이며 군집 간 격차 ≤ 5%p**입니다(→ `03_ALGORITHMS_AI.md` §2.2).

**참여 시민을 DID로 세지 않습니다.** 한 사람이 기기를 5대까지 등록할 수 있으므로(D21) DID로 세면 한 사람이 다섯 명으로 잡힙니다. 사람 단위로 세야 하는 숫자이므로 반응의 익명 필명으로 셉니다(→ `02_IDENTITY_PRIVACY.md` §4).

**자동 생성하지 않습니다.** 조건을 채우지 못한 안건도 문서를 볼 수 있고, 대신 머리말에 **"발행 기준에 못 미칩니다"** 와 부족한 항목이 찍힙니다. 감추고 안 보여주는 것보다 표본이 작다는 사실을 문서 안에서 말하는 편이 낫습니다 — 감추면 읽는 쪽이 기준을 확인할 방법이 없습니다.

발행 전 초안을 7일간 공개해 이의신청을 받는 절차는 VS-H2입니다(미착수). 시민이 만든 문서가 시민 모르게 나가서는 안 됩니다.

### 1.2 문서 양식

**7절 구성입니다.** `14_USER_JOURNEY.md` §3 ⑦의 일곱 가지 필수 수록 항목과 1:1로 맞췄습니다.

```markdown
# [정책 권고서] 탄력 근로제 및 지역 보조금 개선안

* 분야: 정부정책
* 소관: 고용노동부
* 작성일: 2026-04-01
* 공론장: https://open-agora.vercel.app/policies/<id>

## 1. 주제와 쟁점        쟁점 질문 · 배경 · 공식 출처
## 2. 참여 규모          참여 시민 · 의견 · 댓글 · 이념 군집 (표)
## 3. 찬반 분포와 수렴도  3열 분포 + 수렴도 (계산법을 숫자 옆에 함께 적는다)
## 4. 진영을 넘은 합의    2차 관문 통과 대안. 군집별 찬성률·격차·b_i·f_i·카드 식별자
## 5. 합의에 이르지 못한 쟁점  격차 큰 순 5건
## 6. 대표 의견 원문      입장별 2건씩. 원문 그대로
## 7. 검증 정보          앵커 루트·영수증·잎 목록 · 모델 버전·시드·스냅샷 해시 · 군집화 방법

---
이 문서는 CivicAgora 공론장의 집계 결과이며, 특정 개인이나 단체의 공식
입장이 아닙니다. 내려받은 회원이 본인 판단으로 활용하는 자료입니다.
모든 수치는 위 검증 주소에서 직접 재계산할 수 있습니다.
```

**"발신 / 수신" 머리말을 두지 않습니다.** D18로 플랫폼 발송을 폐기했으므로 발신자가 없습니다. 회원이 내려받아 본인 명의로 씁니다. 머리말에 "CivicAgora 거버넌스"를 적는 순간 *누가 시민을 대표하는가* 라는 물음이 생기고, 그것은 이 플랫폼이 만들지 않기로 한 물음입니다.

**개인의 $f_u$는 싣지 않습니다.** 카드 단위 $b_i$·$f_i$만 공개합니다(INV-2). 문서에 카드 식별자를 함께 적어 두면 읽는 쪽이 오픈 API(§2)의 값과 대조할 수 있습니다.

#### 수렴도

$$\text{수렴도} = \frac{1}{|C|}\sum_{i \in C} \min_{k} \; r_{i,k}$$

카드마다 **가장 낮은 군집의 찬성률**을 구해 평균합니다. $C$는 군집이 둘 이상에서 집계된 카드입니다. **평균이 아니라 최솟값**을 쓰는 이유는 한 진영의 몰표로 올릴 수 없게 하기 위해서입니다 — 상세와 근거는 D24에 있습니다.

#### 내려받기 형식

| 형식 | 만드는 곳 |
|-|-|
| TXT | 서버가 마크다운을 그대로 내려줌 |
| DOCX | 서버 (`web/lib/brief-docx.ts`, `docx` 패키지). 같은 마크다운을 문단으로 변환 |
| PDF | **브라우저 인쇄.** 서버에서 만들지 않음 |

PDF를 서버에서 만들지 않는 이유는 한글 글꼴입니다. 글꼴 파일을 함께 실어야 하고, 라이선스와 용량을 감당해도 기기마다 다르게 보입니다. 브라우저 인쇄는 사용자가 이미 가진 글꼴로 뽑습니다. 권고서 화면에는 인쇄용 CSS가 있어 버튼·머리말이 함께 찍히지 않습니다.

DOCX를 마크다운에서 변환하는 것은 **형식마다 따로 쓰지 않기 위해서**입니다. 따로 쓰면 TXT와 DOCX의 내용이 갈리고, 그 차이는 두 파일을 나란히 열어 보는 사람에게만 보입니다.

### 1.3 5절과 7절이 필수인 이유

합의 사항만 골라 보내면 이 문서는 선전물이 됩니다. **합의에 이르지 못한 쟁점과 그 격차를 함께 보고**해야 읽는 기관이 여론 지형을 정확히 파악할 수 있고, 플랫폼이 특정 결론을 밀어붙이지 않는다는 신뢰를 얻습니다. 방법론 고지 역시 수치를 독립 검증할 수 있게 하는 필수 항목입니다.

**읽는 쪽이 저희를 믿을 이유가 없습니다.** 그러므로 믿지 않고도 확인할 수 있는 방법을 줘야 합니다. 7절이 앵커 머클 루트와 영수증 주소, 모델 버전·시드·스냅샷 해시를 싣는 이유입니다. 확인 방법을 감추면 이 문서는 또 하나의 "믿어 주세요"가 됩니다.

두 절은 **실을 것이 없어도 지우지 않고, 없다고 적습니다.** 5절에 실을 것이 없으면 "군집 간 평가가 갈린 의견이 아직 집계되지 않았습니다"라고, 앵커가 없으면 "이 부분은 저희를 믿어야 하는 구간입니다"라고 적습니다. `e2e-brief.mjs`가 두 절의 존재를 시험합니다.

**인용은 지어내지 않습니다.** 6절의 대표 의견은 공론장의 글을 글자까지 그대로 옮깁니다. 요약하거나 다듬는 순간 이 문서는 공론장의 기록이 아니라 플랫폼의 주장이 됩니다.

### 1.4 발송

> **D18로 바뀌었습니다.** 플랫폼이 기관에 보내지 않습니다. 회원이 내려받아
> **본인 명의로** 민원·청원·의원실 제출에 씁니다. 아래는 VS-H2에서 붙일
> 변환·공개 절차이며, 발송 주체는 여전히 회원입니다.

* 국회 의안정보시스템 및 부처 민원 접수 표준 양식으로 **변환해 회원에게 줍니다.**
* 동일 문서를 플랫폼에 영구 공개하고 온체인에 앵커링합니다.
* 회원이 기관 회신을 받아 오면 해당 안건 페이지에 함께 게시할 수 있습니다.

## 2. 연구자용 오픈 데이터 API

"열린 정치 데이터를 정치 연구에 쓰이게 한다"는 원본 목표를 구현하되, 프라이버시 불변식을 지킵니다.

### 2.1 엔드포인트

```
GET /api/v1/research/opinions/export
```

| 파라미터 | 타입 | 필수 | 설명 |
|-|-|-|-|
| `policy_id` | string | ✅ | 안건 고유 식별자 |
| `format` | enum | ⬜ | `json` \| `parquet` \| `csv` (기본 `json`) |
| `since` | date | ⬜ | 해당 일자 이후 데이터만 |

인증 없이 공개하되 IP 단위 요율 제한을 둡니다. 대용량은 Parquet 사전 생성 파일을 CDN으로 제공합니다.

### 2.2 응답

```json
{
  "policy_id": "pol_2026_089",
  "generated_at": "2026-09-21T13:00:00Z",
  "snapshot_root": "0x9f4a...e12d",
  "methodology": { "job": "bridging_mf", "version": "1.0.0", "seed": 20260921 },
  "participant_count": 12480,
  "cluster_count": 2,

      "opinion_id": "op_9812",
      "stance": "ALTERNATIVE",

      "reactions": {
```

### 2.3 기존 명세에서 제거된 필드

기존 문서의 `user_latent_factor: -0.12`는 **삭제되었습니다**(→ D7).

이 필드는 의견마다 작성자 개인의 잠재 정치 성향을 그대로 노출합니다. 원본 요구인 "정치적 성향은 절대 노출되어서는 안 된다"와 정면으로 충돌하며, 여러 안건의 데이터를 결합하면 특정 개인의 성향 좌표를 복원할 수 있습니다.

대신 **카드 단위 편향값 `opinion_bias_factor`($f_i$)** 를 제공합니다. 이것은 "이 글이 어느 진영에 어필하는가"를 나타내는 값으로, 브리징 연구에 필요한 정보를 그대로 담으면서 개인을 식별하지 않습니다.

### 2.4 익명화 규칙

| 규칙 | 내용 |
|-|-|
| **작성자 미포함** | DID·필명 어느 것도 내보내지 않습니다. 작성자별 글 묶음 복원 불가 |
| **최소 인원** | 참여자 50명 미만 안건은 내보내지 않습니다 |
| **군집 최소 인원** | 20명 미만 군집의 찬성률은 `null` 처리합니다 |
| **시간 정밀도** | 시간 단위로 반올림합니다 (분·초 제거) |
| **본문 제외** | 기본 응답에 본문이 없습니다. 본문은 별도 코퍼스 엔드포인트에서 제공 |
| **블라인드 표시** | 검색 제외 처리된 카드는 `is_restricted: true`로 표시하되 본문은 제공하지 않습니다 |

### 2.5 본문 코퍼스

자연어 처리 연구를 위한 별도 엔드포인트입니다.

```
GET /api/v1/research/corpus
```

토론 카드와 댓글의 본문을 제공하되, 작성자 식별자와 반응 데이터를 결합하지 않습니다. 본문과 성향 데이터를 분리해 제공함으로써 문체 기반 재식별 위험을 낮춥니다.

### 2.6 라이선스

* 데이터: **CC BY 4.0**. 출처 표시 시 상업적 이용을 포함해 자유롭게 사용할 수 있습니다.
* 재식별 시도 금지를 이용 약관에 명시합니다.
* API 응답에 `snapshot_root`를 포함해, 연구자가 인용한 데이터가 온체인 앵커와 일치함을 제3자가 확인할 수 있게 합니다. 재현 가능한 정치학 연구의 전제 조건입니다.
