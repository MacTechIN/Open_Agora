# 07. 개발 로드맵

기존 4단계(16주) 로드맵을 네이티브 앱 요구(D14)에 맞춰 개정했습니다. 웹 단독 전제였던 Phase 3이 두 플랫폼 앱으로 확장되면서 전체 기간이 16주에서 **24주**로 늘어납니다.

---

## Phase 0: 기반 정비 (Week 1~2)

앞선 로드맵에 없던 단계입니다. 공유 코어를 먼저 세우지 않으면 두 플랫폼 앱이 각자 다른 방향으로 갈라집니다.

* 모노레포 구조 확정 (`core/`, `apps/`, `services/`, `circuits/`, `contracts/`)
* `civicagora-core` Rust 크레이트 골격 + `civicagora.udl` 인터페이스 초안
* `uniffi-rs` 바인딩 생성 파이프라인 구축 (Kotlin / C# 양쪽 빌드 통과)
* CI: Rust 테스트, 크로스 컴파일(Windows x64, Android arm64/x64), 린트
* **완료 기준** — 양 플랫폼에서 코어의 `version()` 호출이 성공한다

---

## Phase 1: 신원 및 데이터 레이어 (Week 3~8)

* Circom ZK-Email 검증 회로 구현 및 신뢰 설정(trusted setup)
* 검증 스마트 컨트랙트 배포 (테스트넷 → L2 메인넷)
* **코어**: rapidsnark 네이티브 증명 생성, Secp256k1 키 관리, OS 보안 저장소 연동
* ComposeDB 데이터 모델 정의 (`Policy` / `DebateCard` / `Reply` / `Reaction`)
* Helia IPFS 노드 클러스터 및 부트스트랩·릴레이 노드 구축
* **결정 필요**: 허용 이메일 도메인 범위, L2 체인 최종 선택
* **완료 기준** — 실제 이메일로 가입해 Nullifier가 온체인에 기록되고, 중복 가입이 거부된다. Android 실기기에서 증명 생성이 5초 이내에 끝난다

---

## Phase 2: 합의 및 톤 코칭 엔진 (Week 9~14)

* 브리징 행렬 분해 모듈 구현 (Python, 결정론적 재현 보장)
* Pol.is PCA + K-Means 클러스터링, 합의 추출(0.60 / 0.65 2단 관문)
* 톤 코칭 서빙: FastAPI + vLLM, KcELECTRA → kor_unsmile → EEVE 3단 파이프라인
* **코어**: Step 1 온디바이스 스크리닝 (ONNX Runtime 임베딩)
* 산출물 서명·앵커링 및 제3자 재현 검증 도구
* **완료 기준** — 합성 몰표 데이터를 주입했을 때 해당 카드의 $b_i$가 상승하지 않음을 테스트로 증명한다. 이것이 플랫폼 전체의 핵심 회귀 테스트다

---

## Phase 3: 네이티브 앱 (Week 15~20)

* **Android (Jetpack Compose)**: 3탭 토론 뷰(대안 탭 기본 진입), 3단 구조화 입력, 인라인 톤 코칭 배너, 여론 지형도
* **Windows (WinUI 3)**: 3열 동시 표시 토론 뷰, 동일 기능 세트, 접근성 검증
* **코어**: rust-libp2p GossipSub 연동, NAT 통과(AutoNAT + DCUtR + 릴레이 폴백), 오프라인 작성 큐
* Android 백그라운드 동기화 전략(포그라운드 서비스 / WorkManager / Doze 대응)
* 부분 복제 블록스토어 및 용량 상한 관리
* **결정 필요**: 웹에서의 글 작성 허용 여부, Windows UI 언어 최종 확정
* **완료 기준** — 가정용 공유기 하위의 Android 기기와 별도 네트워크의 Windows PC 사이에서 카드가 릴레이 없이 직접 전파된다

---

## Phase 4: 중재 및 평판 (Week 21~22)

* 평판 점수 일 1회 배치 정산 (교차 진영 가점 포함, INV-4 준수)
* 블라인드 3단계 및 공개 중재 로그
* 시민 배심 구성·투표, 이의신청 처리
* SBT 배지 5종 발행 컨트랙트
* 월간 투명성 보고서 자동 생성
* **완료 기준** — 진영별 블라인드 비율이 통계적으로 균형을 이루는지 감사 가능하다

---

## Phase 5: 대정부 파이프라인 및 오픈 API (Week 23~24)

* AI 합의 브리프 자동 생성기 (합의 미도달 쟁점 및 방법론 고지 포함)
* 국회·부처 표준 양식 내보내기
* 연구자용 오픈 데이터 API (DuckDB / Parquet), 익명화 규칙 적용
* 본문 코퍼스 엔드포인트
* 배포: MSIX(Store + 사이드로드), AAB(Play + APK 직배포), 읽기 전용 웹 포털
* **완료 기준** — 발행된 브리프의 모든 수치를 제3자가 공개 스냅샷으로 재계산해 일치시킬 수 있다
