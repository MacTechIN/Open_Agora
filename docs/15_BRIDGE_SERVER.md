# 15. 다리 서버 — 왜 지금 공유 서버를 쓰는가

명세는 중앙 서버 없는 P2P를 규정합니다(`01_ARCHITECTURE.md`). 그런데 현재 배포는 공유 Postgres를 쓰는 서버입니다. **이것은 원칙의 포기가 아니라 다리이며, 그 사실을 감추지 않기 위해 이 문서를 둡니다.**

---

## 1. 왜 이렇게 됐는가

| 시점 | 상태 |
|-|-|
| 명세 | Ceramic ComposeDB에 데이터를 두고 libp2p로 전파 |
| VS-C0 조사 | **ComposeDB가 사실상 중단**(마지막 릴리스 2024-02). 데이터 계층 재선정 필요 |
| 현재 | P2P 계층 없음. 앱마다 로컬 SQLite라 **서로의 글이 보이지 않음** |

공론장의 정의상 서로의 글이 보이지 않으면 제품이 아닙니다. **아무도 쓸 수 없는 공론장은 원칙을 지켜도 의미가 없습니다.**

그래서 공유 서버를 놓아 사람들이 실제로 쓰게 하고, 그 사이에 P2P 계층을 제대로 고릅니다.

---

## 2. 지금 무엇이 취약한가

숨기지 않고 적습니다. 화면에도 표시해야 합니다.

| 명세가 약속한 것 | 현재 |
|-|-|
| 누구도 데이터를 고칠 수 없다 | **서버 운영자는 고칠 수 있다** |
| 삭제가 불가능하다 | 운영자는 DB에서 지울 수 있다 |
| 위변조를 증명할 수 있다 | 서명(VS-A4)도 온체인 앵커(VS-F6)도 없다 |
| 검열할 수 없다 | 서버를 내리면 멈춘다 |

**가장 무거운 것은 첫 줄입니다.** 이 플랫폼의 존재 이유가 "운영자를 신뢰하지 않아도 된다"인데, 지금은 신뢰해야 합니다.

---

## 3. 언제 벗어나는가

순서가 중요합니다. **각 단계가 위 표의 한 줄씩을 지웁니다.**

| 단계 | 슬라이스 | 지워지는 취약점 |
|-|-|-|
| 1 | **VS-A4** 문서 서명 | 운영자가 글을 고치면 서명 검증이 깨져 드러난다 |
| 2 | **VS-F6** 온체인 앵커링 | 삭제와 소급 변경이 머클 루트 대조로 드러난다 |
| 3 | **VS-B2′** Ceramic One 이전 | 데이터 정본이 P2P로 옮겨간다 |
| 4 | **VS-B1** libp2p 전파 | 서버가 멈춰도 참여자끼리 동기화된다 |

1단계만 끝나도 성격이 크게 바뀝니다. 운영자가 여전히 고칠 수는 있지만 **고친 사실이 드러나므로**, 신뢰가 아니라 검증의 문제가 됩니다.

**1단계를 가장 먼저 합니다.** 비용 대비 효과가 가장 크고, P2P 재선정 결과를 기다릴 필요가 없습니다.

---

## 4. 그때 이 서버는 어떻게 되는가

버리지 않습니다. **읽기 게이트웨이**가 됩니다.

```
지금            앱 ──▶ 서버(정본) ──▶ Postgres

나중            앱 ──▶ P2P 망(정본)
                        ▲
                        │
                웹 ──▶ 게이트웨이 노드 ──┘
                      (P2P를 읽어 HTTP로 제공)
```

브라우저는 libp2p 노드를 온전히 돌리기 어렵습니다. 따라서 P2P가 완성돼도 웹에는 게이트웨이가 필요하고, 지금 서버가 그 자리로 옮겨갑니다. **누구나 자기 게이트웨이를 띄울 수 있으므로 중앙화 지점이 되지 않습니다** — IPFS 게이트웨이와 같은 구조입니다.

---

## 5. 설계할 때 지킬 것

다리를 건너는 동안에도 **나중에 P2P로 옮길 수 있는 형태**를 유지합니다.

1. **데이터 모델을 코어와 동일하게 둡니다.** Postgres 스키마가 SQLite 스키마와 같은 모양입니다. 옮길 때 변환이 필요 없습니다.
2. **식별자를 내용 해시로 만듭니다.** 서버가 발번하는 일련번호를 쓰면 P2P로 옮길 때 전부 다시 매겨야 합니다.
3. **검증 규칙을 한 곳에서 관리합니다.** `contracts/limits.json`과 고정 입력으로 코어와 서버를 묶어 둡니다.
4. **서버가 판단하는 것을 만들지 않습니다.** 정렬·집계는 결정론적 계산이어야 하며, 서버만 아는 상태에 의존해서는 안 됩니다.

4번이 특히 중요합니다. 서버에 "서버만 아는 순위 로직"이 생기면 P2P로 옮길 수 없습니다.

---

## 6. 사용자에게 알리기

화면에 현재 단계를 표시합니다. 명세가 약속한 것과 지금 되는 것이 다르다면, 그 차이를 사용자가 알아야 합니다.

> 현재는 준비 단계입니다. 글은 공유 서버에 저장되며, 위변조 방지 서명과
> 블록체인 기록은 아직 적용되지 않았습니다.

이 문구는 VS-A4와 VS-F6이 끝나면 단계적으로 바뀝니다.
