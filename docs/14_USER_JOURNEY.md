# 14. 사용자 여정 — 주제에서 공문서까지

기존 명세는 안건(주제)과 토론 카드(의견)를 각각 정의했지만, **둘이 어떻게 이어지는지**를 적지 않았습니다. 그 결과 구현에서 의견 계층만 만들어졌고, 화면에는 "찬성인데 무엇이 문제인지 적으라"는 모순이 나타났습니다.

이 문서는 **처음 들어온 시민이 공문서용 자료를 손에 쥐기까지의 전 과정**을 하나로 잇습니다.

---

## 1. 무엇이 잘못됐는가

```
기존 구현            [의견 카드]  ← 찬성/반대  ← 무엇에 대한 찬반인가?
                         ↑
                    (비어 있음)
```

**찬반은 주제가 아니라 쟁점 질문에 대한 것입니다.**

* 주제: "탄력 근로제 개선"  ← 여기엔 찬반이 없다
* 쟁점 질문: "직종별 유연 적용을 허용해야 하는가?"  ← 여기에 찬반이 성립한다

명세(`00_PRODUCT_SPEC.md` §6)는 안건에 `쟁점 질문` 필드를 이미 규정했지만 화면에 반영되지 않았습니다. 구현이 명세의 절반만 만든 것입니다.

**그리고 질문이 정해지면 입력 칸도 입장에 따라 달라져야 합니다.** 찬성하는 사람에게 "무엇이 문제인가"를 묻는 것은 답할 수 없는 질문입니다.

---

## 2. 전체 흐름

```
 ① 주제 올리기            시민이 공론화할 주제를 제시하고 자기 의견을 함께 남긴다
        ↓
 ② 광장                  올라온 주제들을 한눈에 본다 (참여자·찬반 분포·수렴도)
        ↓
 ③ 주제 상세             찬성 | 대안 | 반대 3열로 의견을 본다
        ↓
 ④ 의견 쓰기 · 댓글       AI가 쓰는 중에 표현을 코치한다
        ↓
 ⑤ 반응                  💡🤝🔍⚖️ — 반대 진영의 인정이 점수를 만든다
        ↓
 ⑥ 합의 도출             양 진영이 모두 수긍한 대안이 위로 올라온다
        ↓
 ⑦ 보고서 받기            회원이 PDF·DOCX·TXT로 내려받아
                         민원·청원·의견제출에 근거 자료로 쓴다
```

---

## 3. 단계별 설계

### ① 주제 올리기 — 주제와 첫 의견을 함께 받는다

주제만 던지고 빠지는 것을 막습니다. 주제를 여는 사람은 **자기 입장도 함께 밝혀야** 합니다.

**1부: 무엇을 공론화하려 하는가**

| 필드 | 최대 | 설명 |
|-|-|-|
| 주제 제목 | 60자 | 중립적 서술. 찬반을 유도하는 제목은 AI가 경고 |
| 분류 | — | 정부정책 · 입법안 · 정당정책 · 지자체 · 공공기관 · 사회현안 · 문제고발 |
| **왜 지금 이슈인가** | 300자 | 배경. 이 주제가 왜 논의되어야 하는지 |
| **쟁점 질문** | 100자 | **찬반이 성립하는 하나의 질문.** 이것이 토론의 축이다 |
| 공식 출처 | URL | 법령·의안·보도자료 등 1차 자료 |
| 소관 기관 | — | 선택. 나중에 보고서 수신처가 된다 |

**2부: 나는 이 질문에 어떤 입장인가** → ②의 의견 작성 폼과 동일

쟁점 질문이 이 설계의 핵심입니다. **질문이 제대로 서면 찬반이 의미를 갖고, 질문이 흐리면 토론 전체가 흐려집니다.** 따라서 주제 등록 화면은 예시를 통해 좋은 질문을 유도합니다.

```
좋은 쟁점 질문
  "직종별로 탄력 근로제 적용 기준을 달리해야 하는가?"
  "지자체 예산으로 지역화폐를 계속 발행해야 하는가?"

피해야 할 질문
  "탄력 근로제는 어떻게 생각하시나요?"      ← 찬반이 성립하지 않는다
  "잘못된 탄력 근로제, 폐지해야 하지 않나?"  ← 답이 정해져 있다
```

### ② 의견 쓰기 — 입장에 따라 묻는 것이 달라진다

**같은 세 칸이되 질문이 바뀝니다.** 이것이 "찬성인데 문제를 적으라"는 모순을 없애는 방법입니다.

| 입장 | ① (150자) | ② (200자) | ③ (150자) |
|-|-|-|-|
| **찬성** | 왜 이 방향이 옳다고 보시나요? | 어떤 근거가 있나요? | 잘 되려면 무엇이 필요할까요? |
| **대안** | 어떤 점이 아쉬운가요? | 어떤 근거가 있나요? | 어떤 대안을 제안하시나요? |
| **반대** | 무엇이 문제인가요? | 어떤 근거가 있나요? | 대신 어떻게 하면 좋을까요? |

가운데 칸(근거)과 출처 URL은 입장과 무관하게 같습니다. **근거는 어느 입장이든 필요합니다.**

내부 데이터 구조는 바뀌지 않습니다. 세 필드의 의미는 "논점 · 근거 · 제안"으로 동일하고, 화면에 보이는 질문만 입장에 맞춰집니다.

### ③ 광장 — 주제들을 한눈에

주제 목록을 **지금 무엇이 활발한지 바로 읽히는 형태**로 보여줍니다.

```
┌──────────────────────────────────────────────────────────┐
│ 탄력 근로제, 직종별로 기준을 달리해야 하는가?            │
│ 고용노동부 · 입법안                          3시간 전 활동│
│                                                          │
│ 찬성 ████████████░░░░░░░░░░░░ 반대      수렴도 72%       │
│         42%          8%  50%                             │
│                                                          │
│ 시민 1,284명 · 의견 312건 · 댓글 890건    ★ 합의안 2건   │
└──────────────────────────────────────────────────────────┘
```

* 찬반 분포를 **한 줄 막대**로 보여줍니다. 가운데 회색이 대안입니다.
* **수렴도**는 브리징 알고리즘이 계산한 값입니다. 높을수록 양 진영이 접점을 찾았다는 뜻입니다.
* 정렬: `활발한 순` · `최신순` · `수렴도 높은 순` · `보고서 발행 임박순`

> 이 화면은 "거래소 시세판처럼" 요청된 것입니다. 다만 **숫자가 경쟁을 부추기지 않도록** 주의합니다. 참여자 수보다 수렴도를 크게 보여주는 이유가 그것입니다. 많이 모인 주제가 아니라 **합의에 다가간 주제**가 돋보여야 합니다.

### ④ AI 톤 코칭 — 검열이 아니라 코치

쓰는 중에 동작합니다. 사용자는 **언제나 원문 그대로 올릴 수 있습니다.**

```
  ┌ 잠깐만요 ─────────────────────────────────┐
  │ 이 표현이 정책이 아니라 사람을 향하고 있어요. │
  │                                            │
  │ 제안: "해당 지원금 정책은 예산 추계의       │
  │        구체성이 부족합니다"                 │
  │                                            │
  │ [제안대로 바꾸기]     [그대로 올리기]       │
  └────────────────────────────────────────────┘
```

「그대로 올리기」를 고르면 점수가 차감되고 노출 순위가 내려갑니다. **막지는 않습니다.** 막는 순간 검열이 되기 때문입니다(`docs/11_SOVEREIGN_JUDGMENT.md`).

### ⑤ 반응과 점수 — 반대편의 인정이 가장 값지다

| 반응 | 의미 |
|-|-|
| 💡 논리적이에요 | 동의하지 않아도 논증은 타당하다 |
| 🤝 공감해요 | 주장에 동의한다 |
| 🔍 팩트체크 필요해요 | 근거가 의심스럽다 |
| ⚖️ 이견 있어요 | 논지에 동의하지 않는다 |

점수는 **누가 눌렀느냐**에 따라 다릅니다.

```
반대 입장 시민이 💡·🤝 를 누름  →  +5점
같은 입장 시민이 💡·🤝 를 누름  →  +1점      (5배 차이)
```

**내 편을 모으는 것보다 반대편을 설득하는 것이 다섯 배 가치 있습니다.** 이것이 이 플랫폼이 다른 커뮤니티와 갈리는 지점입니다.

`💡 논리적이에요`는 "내 입장은 아니지만 말은 맞다"를 표현하는 통로이며, 화면에서 가장 먼저·크게 배치합니다.

### ⑥ 합의 도출

양 진영 모두에서 60% 이상 찬성을 받은 대안이 **합의 배너**로 올라옵니다. 한쪽만 밀어주는 글은 아무리 반응이 많아도 올라오지 않습니다(`docs/03_ALGORITHMS_AI.md` §1.3).

### ⑦ 보고서 받기 — 회원이 직접 내려받는다

**여기가 기존 명세에서 가장 크게 바뀐 부분입니다.**

기존 설계는 플랫폼이 "발신: CivicAgora 시민 공론장 거버넌스"로 국회·부처에 **직접 발송**하는 것이었습니다. 이를 **회원이 내려받아 본인 명의로 활용**하는 방식으로 바꿉니다(→ `08_DECISIONS.md` D18).

**발행 조건**

| 조건 | 기준 |
|-|-|
| 누적 의견 | 100건 이상 |
| 참여 시민 | 50명 이상 |
| 이념 군집 | 2개 이상 형성 |
| 합의 대안 | 1건 이상 |

> 기존 기준(1,000건·500명)은 초기 플랫폼에서 도달 불가능했습니다. 실제로 쓰이려면 낮춰야 합니다. 대신 보고서에 표본 규모를 명시해 읽는 사람이 무게를 판단하게 합니다.

**내려받는 형식**

| 형식 | 용도 |
|-|-|
| **PDF** | 민원·청원 첨부. 서식이 고정되어 그대로 제출 가능 |
| **DOCX** | 의원실·부처 제출 전 본인이 내용을 덧붙일 때 |
| **TXT** | 온라인 민원 창구 본문에 붙여넣을 때 |

**보고서에 반드시 들어가는 것**

1. 주제와 쟁점 질문
2. 참여 규모 (시민 수·의견 수·댓글 수)
3. 찬반 분포와 수렴도
4. **진영 초월 합의 사항** — 양쪽이 모두 수긍한 지점
5. **합의에 이르지 못한 쟁점** — 숨기지 않는다
6. 대표 의견 원문 (지어내지 않고 실제 글을 인용)
7. 검증 정보 — 온체인 앵커 해시, 재계산 방법, 모델 버전

5번과 7번이 특히 중요합니다. 합의만 골라 실으면 선전물이 되고, 검증 정보가 없으면 읽는 기관이 신뢰할 근거가 없습니다.

**문서 하단 고지**

> 이 문서는 CivicAgora 공론장의 집계 결과이며, 특정 개인이나 단체의 공식 입장이 아닙니다. 내려받은 회원이 본인 판단으로 활용하는 자료입니다. 모든 수치는 위 검증 주소에서 직접 재계산할 수 있습니다.

## 4. 왜 회원 다운로드가 더 나은가

| | 플랫폼 직접 발송 (기존) | 회원 다운로드 (변경) |
|-|-|-|
| 대표성 | "누가 시민을 대표하는가" 논란을 부른다 | 각 회원이 본인 명의로 쓴다. 논란 없음 |
| 법적 책임 | 플랫폼이 진다 | 활용한 개인이 진다 |
| 실제 경로 | 기관이 무시하면 끝 | 민원·청원·국민신문고 등 **기존 제도에 얹힌다** |
| 운영 부담 | 기관별 양식·수신처 관리 | 없음 |
| 도달 범위 | 지정 기관만 | 국회의원실, 지자체, 언론, 학계 등 회원이 판단 |

**결정적인 차이는 "기존 제도에 얹힌다"는 점입니다.** 새 채널을 만들어 기관이 봐주길 기다리는 대신, 이미 작동하는 민원·청원 절차에 **근거 자료로 첨부**되게 하는 편이 실제로 닿습니다.

## 5. 개발 계획 반영

| 슬라이스 | 변경 |
|-|-|
| **VS-A3** (완료) | 의견 카드 저장·조회. 그대로 둔다 |
| **VS-A3′** (신규) | **주제 등록 + 첫 의견 동시 작성.** 쟁점 질문 포함. 규모 M |
| **VS-D1** | 3열 토론 뷰 — 주제 상세 화면. 입장별 질문 전환 포함 |
| **VS-D1′** (신규) | **광장 목록 화면.** 찬반 분포 막대, 수렴도, 정렬 |
| **VS-H1** | 보고서 생성 — 발행 조건을 100건·50명으로 하향 |
| **VS-H2′** (변경) | **회원 다운로드(PDF·DOCX·TXT).** 기관 직접 발송을 대체 |

임계 경로가 바뀝니다. 기존에는 `A3 → B1 → D1`이었으나, 주제 계층이 없으면 3열 뷰를 만들 수 없으므로 **`A3 → A3′ → D1`** 이 됩니다.
