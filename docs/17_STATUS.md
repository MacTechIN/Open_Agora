# 17. 현재 개발 상황

**기준일: 2026-09-25** (VS-A4·VS-F6·VS-C3a·VS-D2·VS-F1/F2/F3·VS-E1 반영)

이 문서는 *계획*이 아니라 *실측*입니다. 계획은 `09_DEVELOPMENT_PLAN.md`에 있고,
여기에는 **지금 실제로 도는 것**만 적습니다. 둘이 어긋나면 이 문서가 사실이고
계획이 늦은 것입니다.

---

## 1. 한 줄 요약

주제를 올리고 세 입장으로 의견을 다는 공론장이 **웹·Windows·Android 세 곳에서
같은 데이터로 동작**합니다. 새로 올라오는 글은 **작성자 기기 키로 서명**되고,
6시간마다 **비트코인에 앵커링**됩니다. 운영자가 고치면 서명이 깨지고, 지우면
앵커와 맞지 않게 됩니다. 브리징·톤 코칭은 아직 없습니다.

## 2. 지금 쓸 수 있는 것

| 창구 | 주소 | 상태 |
|-|-|-|
| 웹 | https://open-agora.vercel.app | 배포됨 |
| Windows | GitHub Releases `dev` → `CivicAgora-windows-x64.zip` | 배포됨 |
| Android | GitHub Releases `dev` → `CivicAgora-android.apk` | 배포됨 |
| iOS | `apps/ios/` | 뼈대만. 맥에서 빌드해야 함 |

`dev`는 main에 푸시할 때마다 갱신되는 프리릴리스입니다. 링크가 바뀌지 않으므로
그대로 공유할 수 있습니다.

**할 수 있는 일**: 이메일 인증 → 주제 열기(첫 의견 필수) → 다른 주제에 의견 달기
→ **의견에 댓글 달기** → 검색·분류·정렬로 찾기.

**기기를 바꾸거나 앱을 새로 깔면 같은 이메일로 다시 인증하면 됩니다.** 시민 ID는
기기 밖으로 나오지 않으므로 기기마다 다른 ID가 되고, 재인증은 새 가입이 아니라
**기기 추가**입니다(한 이메일 최대 5대, D21).

**익명으로 할 수 있는 일** (12단어 복구 문구 필요, 웹에서만)

- 주제에 **지지** 남기기 — 한 사람이 한 번만 (VS-C3a)
- 의견에 **반응** 💡🤝🔍⚖️ — 한 카드당 하나, 바꿀 수 있음 (VS-D2)

둘 다 **서버도 누가 눌렀는지 알지 못합니다.**

**작성 중 도는 것**: 거친 표현이 섞이면 기기 안에서 한 줄 안내가 뜹니다(VS-E1).
**막지 않고**, 타이핑 내용은 기기 밖으로 나가지 않습니다.

**할 수 없는 일**: 톤 코칭 2·3단계(정밀 분류·순화문 제안), 여론 지형도, 합의 배너,
리포트 내려받기.

**운영자가 몰래 할 수 없게 된 일**

- **고치기** — 서명이 깨져 모든 화면에 「⚠ 서명 불일치」가 뜹니다 (VS-A4)
- **소급 조작** — 루트가 비트코인에 남아 있어 나중에 바꿀 수 없습니다 (VS-F6)

**여전히 할 수 있는 일**: 글을 **지우는 것**. 앵커링은 삭제를 막지 않고
드러냅니다 — 그것도 **사본을 가진 사람이 있을 때만**입니다. 그래서 잎 목록을
공개합니다(`/anchors`). 진짜 해결은 데이터 정본을 서버 밖으로 옮기는
P2P(Stack B)입니다.

## 3. 구성 요소별 상태

### 3.1 공유 코어 (`core/`)

Rust, 약 2,600줄, **테스트 89개 통과**.

| 모듈 | 하는 일 |
|-|-|
| `identity.rs` | P-256 공개키 ↔ `did:key`, 서명 검증 |
| `policy.rs` | 주제 모델과 한도 (제목 60 · 배경 300 · 쟁점 질문 100) |
| `card.rs` | 의견 모델과 한도 (논점 150 · 근거 200 · 제안 150) |
| `store.rs` | SQLite. `open_policy`는 주제와 첫 의견을 한 트랜잭션으로 넣음 |
| `api.rs` | 공유 API의 요청 본문 생성과 응답 파싱 |
| `signing.rs` | 작성자 서명의 대상 바이트와 검증 (VS-A4) |
| `merkle.rs` | 앵커링 머클 트리와 증명 (VS-F6) |
| `info.rs` | 빌드 식별 정보 |

바인딩은 `civicagora.udl` 한 곳에서 생성합니다 — Kotlin·C#·**Swift** 3종.
손으로 쓴 FFI 래퍼는 없습니다.

**의도적으로 코어에 없는 것**

- **HTTP 전송.** 각 플랫폼이 OS의 프록시·인증서 정책을 그대로 쓰게 둡니다.
  Rust에 TLS를 넣으면 그것을 잃고 크로스 컴파일 위험도 커집니다.
- **개인키를 다루는 함수.** 키 생성과 서명은 하드웨어 저장소가 합니다.
  코어가 개인키를 다룰 수 있으면 언젠가 다루게 됩니다.
- **삭제·수정 함수.** G-IMMUT.

### 3.2 웹 (`web/`)

Next.js 15.5.25 App Router + Postgres(Neon), Vercel 배포.

- 광장(검색·분류 칩·정렬 4종·보기 3종), 주제 상세 3열, 주제 올리기, 시민 인증
- 쓰기는 **등록된 회원만**. `lib/auth.ts`
- `/api/health`는 설정 **여부만** 보고합니다. 값을 담으면 주소를 아는 누구나
  연결 문자열을 가져갑니다

프라이버시 설계: `consumed_emails`와 `members` 테이블에 **연결 키가 없습니다.**
이메일은 HMAC 해시로만, 가입 시각은 일 단위로 저장합니다. 다만 인증하는
순간에는 서버가 이메일과 DID를 함께 봅니다 — 이 마지막 연결을 끊는 것이
VS-C3(ZK-Email)이고, 그때까지는 사실대로 적어 둡니다.

### 3.3 Windows (`apps/windows/`)

WinUI 3 / Windows App SDK 1.6, .NET 8, 자체 포함 언패키지.

- 웹과 같은 광장 탐색 수단
- 키는 CNG로 만들고 TPM을 우선 사용. `CngExportPolicies.None` — 꺼낼 수 없음
- 릴리스 CI에서 빌드 통과

### 3.4 Android (`apps/android/`)

Jetpack Compose, Kotlin 2.0.21, minSdk 26, cargo-ndk 크로스 컴파일.

- 웹·Windows와 같은 광장 탐색 수단
- 키는 Android Keystore, StrongBox 우선
- 휴대폰에서 3열은 읽히지 않으므로 **세 입장을 같은 크기의 칩**으로 두고
  기본값을 「전체」로 둡니다. 3열이 지키려던 것(어느 쪽도 우대하지 않는다)은
  같습니다
- 릴리스 CI에서 빌드 통과

### 3.5 iOS (`apps/ios/`)

SwiftUI, 배포 타깃 iOS 16, Secure Enclave P-256.

**아직 컴파일된 적이 없습니다.** 맥이 없어 검증하지 못했습니다. 맥에서
`make bootstrap` 후 처음 나는 오류는 예상된 것입니다. `apps/ios/README.md`에
순서와 확인 목록이 있습니다.

`.xcodeproj`는 커밋하지 않습니다 — 병합할 수 없는 파일이라 충돌을 손으로 풀다
보면 조용히 망가집니다. `project.yml`(XcodeGen)만 커밋합니다.

## 4. 계획에서 벗어난 것

`09_DEVELOPMENT_PLAN.md`는 Stack A(골격) 다음에 Stack B(P2P)를 둡니다.
실제로는 **공유 서버와 웹앱을 먼저 만들었습니다.**

**이유**: P2P는 같은 네트워크의 두 기기가 서로를 찾는 것부터 시작합니다.
그 단계에서는 아무도 쓸 수 없고, 쓸 수 없으면 무엇이 틀렸는지도 모릅니다.
공유 서버는 임시 발판이고, 벗어나는 순서는 `15_BRIDGE_SERVER.md`에 있습니다.

**대가**: 서버를 쥔 사람이 글을 **지울** 수 있습니다. 코드에는 삭제 경로가
없지만(G-IMMUT) 데이터베이스 접근 권한이 있으면 지울 수 있습니다.

VS-A4로 **고치는 것**은 막았습니다 — 고치면 서명이 깨져 화면에 드러납니다.
남은 것은 지우는 것이고, 그것은 대조할 대상이 사라지므로 서명으로 막히지
않습니다. VS-F6(앵커링) → VS-B(P2P) 순서로 갚습니다.

웹앱도 계획에 없던 것입니다(원래는 VS-H4의 읽기 전용 포털). 쓰기를 허용한 것은
`08_DECISIONS.md` 미결 사항 중 "웹에서의 글 작성 허용 여부"에 해당하므로,
**임시 결정**으로 두고 Phase 3 전에 확정해야 합니다.

## 7. 열린 항목

### 착수 전 확인이 필요한 조사 (VS-C0 잔여)

| 항목 | 기한 |
|-|-|
| naver·daum·nate의 DKIM 셀렉터와 키 길이 | VS-C2 착수 전 |
| 2048비트 기준으로 확보 가능한 허용 도메인 범위 | VS-C2 착수 전 |
| Gmail의 현재 활성 셀렉터 | VS-C2 착수 전 |
| Ceramic One 앵커링 운영 주체 | VS-B2′ 안에서 |

### 확정이 필요한 결정

- **웹 쓰기 허용** — 지금 허용 중이나 임시. `08_DECISIONS.md` 미결 사항
- **L2 체인 선택** — 앵커링에는 더 이상 필요 없습니다(D20). Semaphore(1인
  1계정)와 SBT 배지를 붙일 때 다시 필요합니다
- **성향 자기 신고 수집 여부** — Phase 1 전
- ~~**1인 1표 보장**~~ — VS-C3a로 해소. 반응·투표는 DID가 아니라 익명 증명으로
  세야 합니다

### 검증되지 않은 것

- iOS 앱 전체 (컴파일된 적 없음)
- Windows 앱의 실행 (빌드는 통과, 실행은 사용자 확인 필요)
- 브리징 랭킹 — 합성 반응으로는 확인했으나 **실제 사용자 반응으로는 아직**
  입니다. 라이브에 반응이 0건이라 배치가 돌 것이 없습니다
- 네이티브 앱의 서명 경로 — 코드는 붙었으나 **실기기에서 글을 올려 보지
  않았습니다.** 확인한 것은 웹 경로입니다
- **자기 카드에 반응하기** — 화면에서만 막습니다. 카드 작성자는 DID로,
  반응자는 필명으로 표시되고 둘이 이어져 있지 않아 서버가 판단할 수 없습니다
- 네이티브 앱의 익명 참여·반응 — 웹에만 붙였습니다. 톤 스크리닝은 네 플랫폼
  모두 붙어 있습니다. Semaphore 를 Rust 코어에 넣는
  일이 남았고, 그 전까지 앱에서는 지지를 누를 수 없습니다
- 앵커 영수증의 **비트코인 확정** — 제출과 표준 형식은 확인했으나, 블록에
  들어가려면 몇 시간이 걸립니다. 확정 뒤 `ots upgrade` 로 확인해야 합니다
