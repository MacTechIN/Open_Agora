# 브리징 배치 (VS-F1 · VS-F2)

정책 토론용으로 변형한 브리징 행렬 분해입니다. 목적은 하나 —
**특정 진영의 몰표로는 상위 노출을 살 수 없게 만드는 것.**

```
r̂(u,i) = μ + b_u + b_i + f_u · f_i
```

`b_i` 가 카드의 브리징 점수이고 랭킹의 기준값입니다.

## 돌리는 법

```bash
cd services/bridging
python3 -m pytest test_bridging.py -q     # VS-F2 회귀 테스트
```

의존성은 numpy 뿐입니다(`requirements.txt`).

## 이 폴더에서 가장 중요한 것

`test_bridging.py` 입니다. **이 테스트가 실패하면 이 플랫폼은 그냥 또 하나의
인기투표 사이트입니다.** 랭킹·반응·평판을 건드리는 모든 변경이 여기를 지나야
하며, CI 에 영구 등록되어 있습니다.

시험은 몰표 카드와 브리징 카드에 **같은 수의 긍정**을 줍니다. 긍정 수로 줄
세우는 랭커는 둘을 구분하지 못하므로, 점수가 갈린다면 그것은 표의 개수가
아니라 **누가 눌렀는가**를 본다는 뜻입니다. 몰표만 1.8배로 늘린 경우도
둡니다 — 표를 더 사도 이기지 못해야 "살 수 없다"가 성립합니다.

## 절편 정규화가 왜 따로 있는가

명세는 원래 정규화를 λ 하나로 적었습니다. 그대로 구현했더니 **몰표가
브리징을 이겼습니다.**

한 진영만 반응하면 그 사람들의 `f_u` 가 거의 상수라 설계행렬 `[1, f_u]` 의 두
열이 거의 평행해집니다(공선성). 이때 릿지는 노름이 큰 상수열, 즉 **절편**으로
설명을 몰아줍니다. 몰표의 긍정이 편향 `f_i` 가 아니라 품질 `b_i` 로 들어가
버립니다.

절편을 더 비싸게 만들면 같은 설명을 `f_i` 로 하는 편이 싸집니다. 양 진영이
모두 긍정한 카드는 `f_u` 부호가 갈려 `f_i` 로 설명할 수 없으므로 그때는
절편이 비싸도 `b_i` 가 올라갑니다.

`test_절편_정규화가_약하면_성질이_깨진다` 가 이 사실을 못박습니다. 깨지는 것을
확인하는 시험이라 이상해 보이지만, **깨진다는 사실이야말로 이 파라미터의 존재
이유**입니다. 나중에 "λ 를 하나로 합치자"는 정리가 들어오면 그 시험이 막습니다.
